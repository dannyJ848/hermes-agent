INTERACTION AUDIT (Multiple components interacting unexpectedly)
================================================================================

[UNAUDITED] Muon + bfloat16 interaction:
  - zeropower_via_newtonschulz5 uses bfloat16 explicitly
  - But Newton-Schulz requires high precision for convergence
  - RISK: Orthogonalization may fail silently in bfloat16
  - DEBUG: Check if exp_avg norms become NaN or diverge
  - MITIGATION: Use float32 for orthogonalization, cast back

[UNAUDITED] TransformerEncoderLayer + batch_first=True:
  - PyTorch's TransformerEncoderLayer expects (seq, batch, feat) by default
  - batch_first=True changes to (batch, seq, feat)
  - RISK: If any library code assumes old format, shapes mismatch
  - DEBUG: Verify all custom attention code uses batch_first consistently

[UNAUDITED] DART + SSD simultaneous forward:
  - Both compute parallel heads from same hidden_states
  - CUDA streams may serialize them unnecessarily
  - RISK: Slower than expected due to stream synchronization
  - DEBUG: Use torch.cuda.Event to measure actual parallelism
  - MITIGATION: Explicit CUDA stream assignment for each graft

[UNAUDITED] Gradient clipping + Muon interaction:
  - clip_grad_norm_ modifies gradients in-place
  - Muon also modifies gradients via orthogonalization
  - RISK: Order matters — clip after Muon may undo orthogonalization
  - CURRENT ORDER: backward → clip → Muon.step (correct?)
  - ACTUAL: backward → clip → optimizer.step (Muon inside step)
  - RISK: Muon orthogonalization happens AFTER clipping — may re-scale
  - DEBUG: Compare loss curves with/without clipping

[UNAUDITED] Shared weights + optimizer interaction:
  - embed_tokens and lm_head are shared from target model
  - But they are in optimizer's parameter list
  - RISK: Shared weights get updated by draft training
  - IMPACT: Target model weights drift — may affect hidden states quality
  - MITIGATION: Freeze shared weights: embed_tokens.requires_grad = False

EMERGENT BEHAVIOR AUDIT (Complex system-level failures)
================================================================================

[UNAUDITED] Loss term interference:
  - 5 loss terms with different scales and frequencies
  - Over 50,000 steps, rare combinations may cause instability
  - Example: DART loss spikes on rare token, causes gradient spike,
    triggers NaN detection, skips batch, reduces effective dataset
  - RISK: Training may "learn" to avoid certain inputs
  - MITIGATION: Per-loss gradient clipping, not just global

[UNAUDITED] Mode collapse cascade:
  - If SSD collapses to head 0, DART may compensate by being more diverse
  - But DART diversity may trigger LTD to be more conservative
  - Result: System finds degenerate equilibrium
  - RISK: Suboptimal but stable — hard to detect
  - DETECTION: Monitor cross-graft metrics, not just individual losses

[UNAUDITED] Checkpoint size explosion:
  - 10B params × 2 bytes = 20GB per checkpoint
  - With optimizer state: 40GB
  - Save every 500 steps = 40 checkpoints per epoch = 1.6TB
  - RISK: Disk full mid-training
  - MITIGATION: Keep only last 3 checkpoints, delete older ones

[UNAUDITED] Hidden states staleness:
  - Phase 1 generated hidden states from target model
  - But target model is NOT frozen during draft training
  - Wait — target model is deleted after weight extraction
  - So hidden states are from ORIGINAL target model
  - RISK: If target model updated later, hidden states become stale
  - MITIGATION: Regenerate hidden states if target model changes

[UNAUDITED] Dataset ordering bias:
  - DataLoader shuffle=True uses default random seed
  - But we set seed at start — shuffle is deterministic per run
  - RISK: Same order every run may cause overfitting to sequence
  - MITIGATION: Use different seed for DataLoader than model

[UNAUDITED] Batch size 1 statistical issues:
  - Batch norm not used (good)
  - But gradient variance is high with batch=1
  - RISK: Noisy gradients, slower convergence
  - MITIGATION: Gradient accumulation (simulate larger batch)

[UNAUDITED] Sequence length bias:
  - collate_fn pads to max_len in batch
  - If one sample is 1024 tokens and rest are 100, waste 90% compute
  - RISK: Effective throughput much lower than theoretical
  - MITIGATION: Bucketing — group similar lengths together

[UNAUDITED] Tokenizer vocabulary mismatch:
  - Qwen3.6 vocab size: 152064
  - But DART/SSD heads output 152064
  - If tokenizer was updated after model training, vocab may differ
  - RISK: Out-of-vocabulary tokens during inference
  - DEBUG: Verify tokenizer.vocab_size == config['vocab_size']

[UNAUDITED] Attention mask missing:
  - TransformerEncoderLayer without attention_mask
  - All positions attend to all positions (including padding)
  - RISK: Padding tokens influence real token predictions
  - MITIGATION: Add src_key_padding_mask to TransformerEncoderLayer

[UNAUDITED] Positional encoding missing:
  - TransformerEncoderLayer has built-in position encoding
  - But it's absolute sinusoidal, not learned
  - RISK: May not generalize to positions > max_position_embeddings
  - MITIGATION: Add learned position embeddings or use RoPE

[UNAUDITED] Weight initialization:
  - Default PyTorch init for Linear layers: uniform(-1/sqrt(in), 1/sqrt(in))
  - For 25600×5120 matrix, init range is very small
  - RISK: Vanishing gradients in early training
  - MITIGATION: Use Xavier/Kaiming initialization explicitly

[UNAUDITED] Bias terms missing:
  - self.fc = nn.Linear(..., bias=False)
  - Some Linear layers in DART/SSD also have no bias
  - RISK: Reduced expressivity, harder to learn offsets
  - MITIGATION: Add bias=True, especially for final layers

[UNAUDITED] Dropout missing:
  - No dropout in custom modules
  - TransformerEncoderLayer has dropout=0.1 by default
  - RISK: Overfitting on small dataset (10K samples)
  - MITIGATION: Add dropout to DART/SSD/LTD heads

[UNAUDITED] Learning rate schedule:
  - Constant LR throughout training
  - No warmup, no decay
  - RISK: Early training unstable, late training plateaus
  - MITIGATION: Cosine annealing with warmup

[UNAUDITED] Weight decay interaction:
  - weight_decay=0.1 applied to ALL parameters
  - Including bias terms (if they existed) and LayerNorm weights
  - RISK: LayerNorm scale parameters decay to zero
  - MITIGATION: Separate parameter groups, no decay on norms/bias

[UNAUDITED] Gradient accumulation missing:
  - Effective batch size = 1
  - High gradient variance
  - RISK: Noisy updates, slower convergence
  - MITIGATION: Add --gradient-accumulation-steps flag

[UNAUDITED] Mixed precision training:
  - Model in bfloat16, but some ops may upcast to float32
  - RISK: Slower than necessary, more memory than needed
  - MITIGATION: Use torch.cuda.amp.autocast for explicit control

[UNAUDITED] CPU offloading:
  - Dataset loads to CPU, then transfers to GPU
  - RISK: Data transfer bottleneck
  - MITIGATION: Use pin_memory=True in DataLoader

[UNAUDITED] Multi-worker data loading:
  - num_workers=0 (main process loads data)
  - RISK: GPU idle while CPU loads next batch
  - MITIGATION: num_workers=2-4 with proper multiprocessing

[UNAUDITED] Memory pinning:
  - No pin_memory in DataLoader
  - RISK: Slow CPU→GPU transfers
  - MITIGATION: Add pin_memory=True

[UNAUDITED] Gradient checkpointing:
  - Not used — full forward graph stored
  - RISK: OOM on longer sequences
  - MITIGATION: Enable gradient checkpointing for transformer layers

[UNAUDITED] torch.compile:
  - Not used
  - RISK: Missing 20-40% speedup from compilation
  - MITIGATION: Add torch.compile(model) if PyTorch 2.0+
  - BUT: torch.compile may crash on custom modules

[UNAUDITED] Distributed training:
  - Single GPU only
  - RISK: Cannot scale if training too slow
  - MITIGATION: Add DDP support for multi-GPU (if available)

[UNAUDITED] Model parallelism:

  - MITIGATION: Add pipeline or tensor parallelism

[UNAUDITED] Quantization during training:

[UNAUDITED] Sparsity:
