AUDIT 1: PERFORMANCE AUDIT
================================================================================

[METRIC] Parameter Count Breakdown:
  Base transformer (8 layers, 5120 hidden, 32 heads):
    - Self-attention: 8 × (5120×5120×3 + 5120×5120) = 8 × 104,857,600 = 838,860,800
    - FFN: 8 × (5120×13824 + 13824×5120) = 8 × 141,557,760 = 1,132,462,080
    - Norms: ~8 × 5120 × 2 = 81,920
    - Total base: ~1.97B params
  
  DART (8 parallel heads):
    - Feature extractor: 5120×5120 + 5120×5120 = 52,428,800
    - Position embeddings: 8 × 5120 = 40,960
    - 8 heads × (5120×5120 + 5120×152064) = 8 × 26,214,400 + 8 × 778,567,680
    - Total DART: ~6.44B params
  
  SSD (4 outcomes):
    - Outcome predictor: 5120×2560 + 2560×4 = 13,107,200 + 10,240
    - 4 preemptive heads × (5120×2560 + 2560×152064) = 4 × 13,107,200 + 4 × 389,283,840
    - Confidence head: 5120×1280 + 1280×1 = 6,553,600
    - Total SSD: ~1.61B params
  
  LTD:
    - State encoder: 5120×2560 + 2560×2560 = 19,660,800
    - 3 policy heads: ~2560×1280×3 + 1280×(16+1+1)×3 = ~9,830,400 + 69,120
    - Total LTD: ~29.6M params
  
  GRAND TOTAL: ~1.97B + 6.44B + 1.61B + 0.03B = ~10.05B params
  
  [WARNING] 10B params is 2.6× larger than standard DFlash (3.87B)
  [WARNING] Checkpoint size: ~40GB per checkpoint (vs 14GB standard)
  [WARNING] Disk usage: 18 checkpoints × 40GB = 720GB (may exceed available space)
  
  MITIGATION: Reduce save_interval from 500 to 1000 steps

[METRIC] Training Speed Estimate:
  Standard DFlash: ~9.7s/it (single forward + backward)
  Franken v8: 
    - Base forward: ~9.7s
    - DART forward: +8 parallel heads ≈ +3-4s
    - SSD forward: +4 preemptive heads ≈ +2-3s
    - LTD forward: +3 policy heads ≈ +0.5s
    - Additional loss computations: +1-2s
    - Total estimate: ~16-20s/it
  
  Per epoch: 9999 steps × 18s = ~50 hours (vs 27 hours standard)
  3 epochs: ~150 hours (~6.25 days)
  
  [RISK] Very long training time — may need to reduce epochs or dataset size

[METRIC] Memory Usage Estimate:
  Model parameters: 10B × 2 bytes (bfloat16) = 20GB
  Gradients: 10B × 2 bytes = 20GB
  Optimizer state (Muon): 10B × 4 bytes = 40GB
  Activations (batch=1, seq=1024): ~5-10GB

  GB10 has 128GB unified memory

[WARNING] Missing connections:

    - Gating mechanism: primary_logits = α×primary + β×dart_best

[WARNING] Loss weight wiring:
  CURRENT: Fixed weights (primary=1.0, dart=0.5, ssd=0.3, ltd=0.2)
  ISSUE: No dynamic balancing — if DART loss is 10× larger, it dominates
  RECOMMENDATION: Add loss normalization:
    loss = primary + (lk/|lk|) + (dart/|dart|) + (ssd/|ssd|) + (ltd/|ltd|)

AUDIT 3: LOGIC AUDIT
================================================================================

[PASS] Primary loss: Standard next-token prediction ✓
[PASS] LK loss: KL divergence between draft and target ✓ (with detach fix)
[PASS] DART loss: Each position head predicts i-th future token ✓
[PASS] SSD loss: Outcome classification + preemptive prediction ✓

[QUESTION] SSD outcome target logic:
  CURRENT: outcome_target = torch.zeros(...)
  LOGIC: Always class 0
  PROBLEM: What does class 0 mean?
  
  POSSIBLE INTERPRETATIONS:
    a) Class 0 = "use preemptive head 0"
    b) Class 0 = "low confidence, use primary"
    c) Class 0 = "default routing"
  
  ISSUE: Without meaningful targets, SSD learns nothing useful
  RECOMMENDATION: Compute optimal outcome per position:
    - For each position, compute which preemptive head has lowest cross-entropy
    - Use argmin as target
    - This makes SSD learn to route to the best head

[QUESTION] LTD reward logic:
  CURRENT: depth_reward = correct_mask.mean()
  LOGIC: More correct predictions → deeper speculation
  ISSUE: Depth reward doesn't depend on actual depth chosen
  PROBLEM: Policy can choose any depth and get same reward
  
  FIX: Make reward depth-dependent:
    - If depth=d and first d tokens correct: reward = d
    - If any token wrong within depth: reward = -1
    - This encourages accurate deep speculation

[WARNING] Exit policy logic:
  CURRENT: exit_reward = 1.0 - correct_mask.mean()
  LOGIC: Low accuracy → high exit probability
  ISSUE: Exit is per-position, but should be per-sequence
  PROBLEM: Exiting mid-sequence truncates generation
  
  FIX: Make exit decision at sequence level:
    - Compute cumulative accuracy
    - Exit when cumulative accuracy drops below threshold

AUDIT 4: REDUNDANCY AUDIT
================================================================================

[REDUNDANCY DETECTED] Multiple confidence mechanisms:
  1. SSD confidence_head: [bsz, seq_len, 1]
  2. LTD confidence_policy: [bsz, seq_len, 1]
  3. Primary logits can derive confidence via softmax entropy
  
  OVERLAP: All three estimate prediction confidence
  WASTE: Training 3 separate confidence estimators
  RECOMMENDATION: Consolidate into single confidence module

[REDUNDANCY DETECTED] Multiple prediction heads:
  1. Primary lm_head: [bsz, seq_len, vocab_size]
  2. DART 8 parallel heads: 8 × [bsz, seq_len, vocab_size]
  3. SSD 4 preemptive heads: 4 × [bsz, seq_len, vocab_size]
  
  TOTAL: 13 separate vocab projection layers
  WASTE: Massive parameter duplication
  RECOMMENDATION: Share vocab projection weights across heads

[REDUNDANCY DETECTED] Multiple layer norms:
  1. AdaptiveRMSNorm in hidden_norm
  2. AdaptiveRMSNorm in norm
  3. LayerNorm in each TransformerEncoderLayer (2 per layer × 8 = 16)
  4. LayerNorm in each DART head (8)
  5. LayerNorm in SSD heads (4)
  6. LayerNorm in LTD state_encoder (1)
  
  TOTAL: 31 normalization layers
  NOTE: May be necessary for stability, but worth monitoring

[REDUNDANCY DETECTED] Position encoding:
  1. TransformerEncoderLayer has built-in position encoding
  2. DART has position_embeddings
  3. Input IDs carry positional information via embed_tokens
  
  OVERLAP: Multiple position representations

AUDIT 5: CONVERGENCE AUDIT
================================================================================

[CONCERN] Loss landscape complexity:
  - 5 separate loss terms with different scales
  - DART loss: ~2-4 (8 cross-entropy terms)
  - SSD loss: ~2-3 (5 cross-entropy terms)
  - LTD loss: ~0.1-0.5 (RL-style, small magnitude)
  - Primary loss: ~2-5
  
  RISK: LTD loss may be drowned out by larger losses
  MITIGATION: Dynamic loss balancing or gradient surgery

[CONCERN] Gradient conflict:
  - DART wants to maximize parallel prediction accuracy
  - SSD wants to maximize outcome prediction + preemptive accuracy
  - LTD wants to maximize speculation depth when confident
  - Primary wants to maximize next-token accuracy
  
  POTENTIAL CONFLICT:
    - DART may learn shortcuts that hurt primary
    - SSD may learn to always route to head 0 (degenerate)
    - LTD may learn conservative depth=1 (safe but slow)
  
  MITIGATION: Gradient projection or PCGrad

[CONCERN] Long training time:
  - 150 hours for 3 epochs
  - Risk of hardware failure, power outage, SSH timeout
  - No distributed training fallback
  
  MITIGATION: 
    - Save checkpoints every 250 steps (not 500)
    - Use tmux/screen for persistent sessions
    - Monitor GPU temperature

AUDIT 7: FAILURE MODE ANALYSIS
================================================================================

SCENARIO 1: NaN explosion (probability: 15%)
  TRIGGER: AdaptiveRMSNorm with very small variance
  DETECTION: NaN check in forward + loss
  RECOVERY: Skip batch, reduce learning rate, increase eps

SCENARIO 2: OOM during training (probability: 10%)
  TRIGGER: Sequence length > 1024 or memory fragmentation
  DETECTION: GPU memory monitoring
  RECOVERY: Reduce batch size, clear cache, restart from checkpoint

SCENARIO 3: Checkpoint corruption (probability: 5%)
  TRIGGER: Disk full, power loss during save
  DETECTION: verify_checkpoint() on load
  RECOVERY: Load previous checkpoint, resume

SCENARIO 4: Gradient explosion (probability: 20%)
  TRIGGER: DART or SSD loss spikes
  DETECTION: Gradient norm monitoring
  RECOVERY: Clip gradients, reduce loss weights

SCENARIO 5: Training stall (probability: 10%)
  TRIGGER: Loss plateaus, no improvement for 1000 steps
  DETECTION: Loss trend monitoring
  RECOVERY: Reduce LR, enable new grafts, data augmentation

SCENARIO 6: SSH disconnect (probability: 30%)
  TRIGGER: Network timeout, laptop sleep
  DETECTION: Process monitoring
  RECOVERY: Use tmux, auto-resume on reconnect
