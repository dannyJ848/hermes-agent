## The 5 New Systems

### 1. Unified Intelligence Engine (`agent/unified_intelligence_engine.py`)

**Purpose**: Cross-system analytics — query across ALL cognitive databases to answer
questions like "What errors correlate with low success rates?" or "Which tips are
validated by actual outcomes?"

**Key insight**: The cognitive apparatus had 5+ separate SQLite databases
(cerebrum_memory.db, cortex, training_gym.db, error_patterns.db) but no way to
JOIN across them. This engine opens connections to all DBs and runs unified queries.

**API**:
```python
from agent.unified_intelligence_engine import UnifiedIntelligenceEngine

ui = UnifiedIntelligenceEngine()

# Query 1: Error-success correlation
insight = ui.query_error_success_correlation(tool_name="terminal")
print(insight.confidence)        # 0.0-1.0
print(insight.recommendation)    # Human-readable summary
print(insight.data)              # Structured data

# Query 2: Tip validation (which tips have proven outcomes?)
insight = ui.query_tip_validation()

# Query 3: Learning velocity per tool
insight = ui.query_learning_velocity(tool_name="patch")

# Query 4: Weakness identification
insight = ui.query_weaknesses()

# Daily briefing (all queries at once)
briefing = ui.generate_daily_briefing()
```

**Schema adaptation pattern**: The engine handles schema drift by trying the ideal
JOIN query first, falling back to simpler queries if columns don't exist:
```python
try:
    rows = db.execute("SELECT ep.error_signature, e.success FROM error_patterns ep JOIN experiences e ON ...").fetchall()
except sqlite3.OperationalError:
    # Fallback: query tables separately
    errors = db.execute("SELECT fingerprint as error_signature, ... FROM error_patterns").fetchall()
```

**Integration**: Called in `session_end()` to generate intelligence briefing for
the session report.

### 2. Predictive Failure Prevention (`agent/predictive_failure_prevention.py`)

**Purpose**: Before-action risk scoring — predict failure probability BEFORE
the tool executes, based on historical failure rates, error patterns, task
complexity, and detail quality.

**Key insight**: Most failures are predictable. If a tool has 80% historical
failure rate for a specific pattern, warn before executing.

**Risk factors weighted**:
- Historical failure rate (30%): How often this tool fails
- Error pattern match (25%): Recurring errors for similar actions
- Task complexity (20%): Detail length, multiple operations, error keywords in context
- Tool oracle uncertainty (15%): Low confidence in tool selection
- Detail quality (10%): Missing required fields for the action type

**API**:
```python
from agent.predictive_failure_prevention import PredictiveFailurePrevention

fp = PredictiveFailurePrevention()
risk = fp.assess_risk(
    action_type="patch",
    detail='{"path": "test.py", "old_string": "x=1"}',
    context="Fixing a bug in production code"
)

print(risk.risk_score)     # 0.0-1.0
print(risk.risk_level)     # 'low', 'medium', 'high', 'critical'
print(risk.proceed)        # True/False recommendation
print(risk.mitigation)     # List of suggested mitigations

# Record outcome to improve future predictions
fp.record_outcome("patch", detail, success=False, error="FileNotFoundError")
```

**Integration**: Called in `before_action()` — if risk is high/critical, injects
a warning into the lessons returned to the agent.

### 3. Autonomous Experimentation Loop (`agent/autonomous_experimentation.py`)

**Purpose**: Self-directed learning — identify weakest areas, generate hypotheses,
run experiments, record results. No human prompting needed.

**Key insight**: Instead of waiting for user to say "practice X", the system
proactively identifies weak areas from unified intelligence and runs training
drills autonomously.

**Experiment lifecycle**:
1. **Identify**: Query unified intelligence for weakest areas (low success rate tools, frequent errors, low training scores)
2. **Hypothesize**: Generate experiment with predicted outcome
3. **Execute**: Run the experiment (training drill, error study, tool practice)
4. **Record**: Save results to `~/.hermes/experiments.jsonl`

**API**:
```python
from agent.autonomous_experimentation import AutonomousExperimentationLoop

exp = AutonomousExperimentationLoop(training_gym=my_gym, unified_engine=my_ui)

# Run a full cycle (up to N experiments)
result = exp.run_cycle(max_experiments=3)
# Returns: {'status': 'completed', 'weaknesses_found': 5, 'experiments_run': 3, 'results': [...]}

# Get statistics
stats = exp.get_experiment_stats()
# {'total_experiments': 47, 'completed': 45, 'failed': 2, 'success_rate': 0.96}
```

**Integration**: Called in `session_end()` via ThreadPoolExecutor — runs
background experimentation after each session.

### 4. Cross-Domain Transfer Learning (`agent/cross_domain_transfer.py`)

**Purpose**: Learn in one domain, apply in another. Maps structural similarities
and proactively suggests transfers.

**Key insight**: Error patterns are domain-agnostic. A "missing delimiter" error
in Python is structurally identical to one in TypeScript or YAML. The system
records patterns per domain and suggests transfers to similar domains.

**Domain similarity matrix** (built-in):
```python
DOMAIN_SIMILARITY = {
    ('python', 'typescript'): 0.85,
    ('python', 'javascript'): 0.80,
    ('docker', 'kubernetes'): 0.75,
    ('json', 'yaml'): 0.70,
    ('patch', 'edit'): 0.85,
}
```

**Pattern templates** (6 built-in):
- `syntax_error`: missing delimiter (applies to python, ts, js, bash, yaml, json)
- `path_error`: invalid path (applies to terminal, read_file, write_file, patch, docker)
- `permission_error`: insufficient permissions
- `timeout_error`: operation timeout
- `format_error`: malformed content
- `dependency_error`: missing dependency

**API**:
```python
from agent.cross_domain_transfer import CrossDomainTransfer

dt = CrossDomainTransfer()

# Record a learned pattern
dt.record_pattern(
    domain="python",
    error_text="ModuleNotFoundError: No module named 'fake'",
    solution="pip install fake",
    success=True
)

# Find transferable patterns for a target domain
suggestions = dt.find_transfers("javascript", limit=5)
# Returns: [TransferSuggestion(source_domain='python', target_domain='javascript', ...)]

# Suggest before executing an action
transfer = dt.suggest_for_action("write_file", '{"path": "test.ts"}', "Creating TypeScript file")
```

**Integration**: Called in `before_action()` — if a high-confidence transfer
exists, injects it into lessons.

### 5. Attention-Based Context Prioritizer (`agent/attention_context_prioritizer.py`)

**Purpose**: Relevance-based memory injection — score every memory unit by
relevance to current task and inject only top-N most relevant. Prevents context bloat.

**Key insight**: Injecting ALL memories into context wastes tokens and distracts
the model. This system scores memories by semantic overlap with the current task
and only injects the most relevant ones.

**Scoring formula**:
```
relevance = task_overlap * 0.35 + context_overlap * 0.25 + recency * 0.20 + type_boost * 0.10 + confidence * 0.10
```

**Type boosts**:
- error_pattern: 1.2x (highest priority — prevents repeated failures)
- tip: 1.1x
- skill: 1.0x
- fact: 0.9x
- trace: 0.7x

**API**:
```python
from agent.attention_context_prioritizer import AttentionContextPrioritizer

ap = AttentionContextPrioritizer(max_memories=5, recency_halflife_hours=24.0)

# Get prioritized memories for current task
memories = ap.prioritize(
    current_task="Debug Python asyncio memory leak",
    current_context="Getting traceback from production logs"
)

# Format for injection
injection = ap.format_for_injection(memories)
# Returns formatted string with [RELEVANT MEMORY CONTEXT] header

# One-shot: get injection string
injection = ap.get_injection("Debug Python asyncio memory leak")
```

**Integration**: Called in `before_action()` — injects relevant memories into
the lessons returned to the agent. Memory cache refreshes every 5 minutes.

## Orchestrator Integration Points

### before_action (3 new hooks added)

```python
def before_action(self, action_type: str, detail: str) -> Optional[str]:
    lessons = []
    
    # ... existing hooks (error_learning, tiered_memory, skill_tracker, trust_scorer) ...
    
    # NEW v2.2: Predictive failure prevention
    if "failure_prevention" in self._subsystems:
        risk = fp.assess_risk(action_type, detail, context_str)
        if risk.risk_level in ('high', 'critical'):
            lessons.append(f"[RISK WARNING] {action_type}: {risk.risk_level.upper()} risk")
    
    # NEW v2.2: Cross-domain transfer
    if "domain_transfer" in self._subsystems:
        transfer = dt.suggest_for_action(action_type, detail)
        if transfer:
            lessons.append(f"[TRANSFER] {transfer.explanation[:200]}")
    
    # NEW v2.2: Attention-based memory injection
    if "attention_prioritizer" in self._subsystems:
        injection = ap.get_injection(f"{action_type}: {detail}")
        if injection:
            lessons.append(injection)
    
    return "\n".join(lessons) if lessons else None
```

## Key Techniques Documented

1. **Multi-database query engine** — Open connections to multiple SQLite DBs, run
   unified queries with schema-adaptive fallbacks
2. **Before-action risk scoring** — Composite score from 5 factors, weighted by
   historical data quality
3. **Self-directed experimentation** — Weakness identification → hypothesis generation
   → autonomous execution → result recording
4. **Domain similarity matrix** — Pre-computed structural similarities enable
   proactive pattern transfer suggestions
5. **Attention-based memory scoring** — Jaccard overlap + recency decay + type boost +
   confidence = relevance score, top-N injection only
6. **Schema-agnostic querying** — Try ideal query first, fall back to simpler queries
   when columns don't exist (handles DB evolution)
