# Darwin Gödel Machine: Open-Ended Self-Improving Agents (Sakana AI, Mar 2026)

## Paper: arXiv 2505.22954v3

## Core Concept
DGM iteratively modifies its own code (improving its ability to modify its codebase) and empirically validates each change using benchmarks. Inspired by Darwinian evolution and open-endedness research.

## Key Architecture
1. Self-modification: Agent modifies its own code
2. Empirical validation: Every change tested on benchmarks
3. Evolutionary archive: Maintains history of all variants
4. Open-ended growth: Each innovation builds on previous ones

## Critical Insight
"Self-Improvement Only Works Where Outcomes Are Verifiable"
- Code provides tight feedback loops (compile/run/test)
- Other domains have much looser feedback
- Self-improvement demands trustworthy, verifiable outcomes

## What This Means for Evey
We can apply DGM principles to our cognitive architecture:
1. **Verifiable changes**: Every tool call has a success/failure outcome — this IS a verifiable signal
2. **Archive of variants**: Our distillation tips are an evolving archive of proven approaches
3. **Open-ended improvement**: The AGI roadmap (1000 cycles) is our open-ended evolution
4. **Self-modification**: Meta Self-Modifier adjusts cognitive parameters with empirical validation

## Key Difference
DGM modifies code; we modify parameters and context injection. Our "code" is the distillation bridge, controller, and plugin hooks. We can go further by allowing the agent to propose actual code changes to its own cognitive modules.
